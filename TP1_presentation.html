1. Hyperviseur : type 1 ou type 2 ?

  • Type 1 : bare-metal, directement sur le matériel. Exemples : Xen, KVM, Hyper-V.
  • Type 2 : installé comme logiciel sur un OS hôte. Exemples : VirtualBox, VMware Workstation.
  • VirtualBox est un hyperviseur de type 2.

Pourquoi c'est important ?

Le type d'hyperviseur influence la performance, la gestion du matériel et les cas d'usage (poste de travail vs cloud).

Hyperviseurs

2. Pourquoi la virtualisation matérielle est indispensable ?

  • VT-x (Intel) et AMD-V (AMD) ajoutent au processeur des modes de virtualisation.
  • Ils permettent à une VM de s'exécuter avec un cloisonnement matériel, sans dépendre d'un système d'exploitation hôte pour gérer chaque instruction.
  • Sans cette prise en charge, une VM 64 bits ne peut pas démarrer correctement.
  • La virtualisation matérielle est donc nécessaire pour faire fonctionner un système invité en sécurité et avec de bonnes performances.

4. Vérifier l'image ISO Ubuntu

  • Le téléchargement d'une ISO ne suffit pas : il faut vérifier son intégrité.
  • SHA-256 est une empreinte cryptographique du fichier.
  • La moindre modification de contenu produit une empreinte différente.
  • La vérification protège contre les fichiers corrompus ou altérés.
  • Idéalement, le fichier SHA256SUMS doit être récupéré depuis une source officielle et vérifié avec GPG.
Intégrité

5. Ubuntu Desktop vs Ubuntu Server

Ubuntu Desktop

  • Interface graphique
  • Applications bureautiques
  • Destiné à un poste de travail

Ubuntu Server

  • Pas d'interface graphique
  • Administration en ligne de commande
  • Moins de ressources, plus sécuritaire

Pour un serveur cloud, Ubuntu Server est le meilleur choix : il consomme moins, expose moins de services et est plus facile à administrer à distance via SSH.

Choix du système

6. LTS : qu'est-ce que cela veut dire ?

  • LTS = Long Term Support.
  • Une version LTS reçoit des mises à jour de sécurité pendant plusieurs années.
  • Ubuntu propose souvent 5 ans de support standard, puis des extensions via Ubuntu Pro.
  • Le choix d'une version LTS est généralement le plus stable et le plus sûr pour un environnement de production.

8. Disque dynamique vs taille fixe

  • Disque dynamique : l'espace utilisé augmente au fur et à mesure, jusqu'à la taille maximale.
  • Disque fixe : toute la capacité est réservée d'avance.
  • Le disque dynamique est souvent préférable pour économiser l'espace disque de l'hôte.
  • À la création, le fichier .vdi est petit et grossit progressivement.

9. Pourquoi désactiver l'installation sans surveillance ?

  • L'installation sans surveillance applique automatiquement des paramètres par défaut.
  • Elle masque les étapes de configuration et limite le contrôle du système.
  • Dans ce TP, on veut maîtriser le nom d'utilisateur, les options réseau et le paramétrage du serveur.
  • Le résultat est un environnement plus explicite et plus conforme au besoin.
Configuration manuelle

10. NAT et redirection de port

  • En mode NAT, la VM est dans un réseau privé virtuel derrière un routeur de VirtualBox.
  • Elle n'est pas directement joignable depuis l'hôte via son adresse interne.
  • La redirection 127.0.0.1:2222 → VM:22 permet d'accéder au service SSH de la VM depuis l'hôte.
  • C'est l'équivalent d'un point d'entrée contrôlé dans un réseau privé d'un cloud.

12. Pourquoi OpenSSH est installé dès le début ?

  • Un serveur ne possède ni clavier ni écran physiques en production.
  • SSH permet l'administration à distance, sécurisée et chiffrée.
  • Sans SSH, il serait impossible de gérer correctement une VM ou un serveur cloud.
  • Il faut aussi copier des fichiers, automatiser les tâches et surveiller le système.

Réseau

14. Pourquoi utiliser 127.0.0.1:2222 ?

  • 10.0.2.15 est une adresse interne au réseau NAT de VirtualBox.
  • L'hôte n'a pas de route directe vers cette adresse privée.
  • La redirection de port de l'hôte permet d'accéder à la VM via localhost : 127.0.0.1:2222.
  • C'est une méthode courante pour administrer une VM depuis le système hôte de manière simple et sécurisée.
Accès SSH

15. Avantages de l'authentification par clé

  • Pas de mot de passe transmis sur le réseau.
  • Une clé SSH est très difficile à deviner et plus fiable qu'un mot de passe faible.
  • Elle facilite les automatisations et les déploiements sans intervention manuelle.
  • Les fournisseurs cloud l'utilisent massivement car les ports SSH sont systématiquement exposés à des attaques automatisées.
Sécurité

16. Snapshot, clone et arrêt propre

  • Instantané : état figé d'une VM ; possibilité de revenir en arrière.
  • Clone : copie indépendante de la VM avec son propre disque et sa propre configuration.
  • acpipowerbutton simule un arrêt propre, en envoyant un signal ACPI à l'invité.
  • poweroff coupe immédiatement l'alimentation, ce qui peut entraîner des corruptions.
Snapshot & clone

17. Pourquoi démarrer en mode headless ?

  • Le mode headless lance la VM sans fenêtre graphique.
  • On économise des ressources de l'hôte.
  • On administre la machine via SSH uniquement.
  • C'est le modèle le plus proche d'une instance cloud : le service est accessible et exploitable sans console locale.
